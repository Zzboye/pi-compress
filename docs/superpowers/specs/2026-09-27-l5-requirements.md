# L5 需求整理

日期：2026-09-27
状态：需求已冻结，待实施
关联 spec：`2026-09-27-l5-per-turn-recompress-design.md`（本文件是它的需求侧提炼）
取代：`2026-09-21-l5-task-aggregation-design.md`（已被探针否证）

---

## 0. 一句话

**L5 从「多个 turn 合并成一行主题描述、且不可召回」改为「每个 turn 各自二次压缩成一条描述、且与 L3/L4 一样可召回整段原文」。**

---

## 1. 为什么改（问题清单）

现状 L5 有四个问题，探针逐一证实：

| # | 问题 | 证据 | 严重性 |
|---|---|---|---|
| P1 | **不可召回** —— L5 是唯一拒绝 recall 的层级，数据在 store 里但主动不给（"数据坟墓"） | `recall.ts:86-91` 拒发分支 | 🔴 功能缺失 |
| P2 | **跨度不可控** —— 一组长度 = reserve 边界落在哪，实测可切出 1436 条 turn 共用一句描述 | `l5-merge-describe-ab.txt` | 🔴 描述质量归零 |
| P3 | **标识保留率 0%** —— 现状 `≤25 字` 契约把文件名/commit/数字全砍掉，与 L4 旧 V0 同病 | `l5-merge-describe-ab.txt`：A 方案 0/209 | 🔴 描述无用 |
| P4 | **假可用性** —— `searchLedger` 能命中 L5 描述并返回并集 ID，但 `recall` 又拒绝 | `recall.ts:239-252` + `86-91` | 🟡 体验矛盾 |

**四个问题同源**：都来自「合并成一行」这个形态。

---

## 2. 需求（要什么）

### R1 · 粒度：一个 turn 一条 L5 描述

- 每条 L4 各自独立生成一条 L5 描述
- **不再有「组」的概念** —— 不存在 `mergeGroups`，不存在组共享描述

**理由**：P2（跨度不可控）与 P3（标识丢失）都是"多条压成一句"的必然结果。合并被探针四方案（A/B/C/D）全面否证——**无一能兼得「主题」与「定位」**。

### R2 · 生成：批量调用，逐条对应

- 一次调用提交 N 条 L4，要求输出 N 条，序号一一对应
- N = 20（硬编码常量，附探针依据注释）
- 失败兜底：某条返回 null/空 → **该条单独重跑一次**；仍失败 → 保持 L4 + warning

**理由**：逐条调用需 900 次（44 分钟）；批量把同量工作压到约 45 次（约 20 分钟），且实测**批量输出反而比单条短 17–39%**。单条重跑而非整批重试——避免放大成本。

### R3 · 召回：与 L3/L4 完全一致

- L5 turn 被 recall → 返回该 turn 的**整段原文**（含工具过程与两端原文）
- 与 L3/L4 走同一条路径，**无任何特殊处理**

**理由**：取消合并后 L5 与 L3/L4 同为「单 turn 降级形态」，没有理由区别对待。旧 spec 的「L3 视图」是合并形态下的折中（一组含多 turn 时整段原文会爆），**取消合并后该理由消失**。

### R4 · 入口：L5 行渲染锚点 ↩ID

- 渲染 `T{n} · {描述} ↩{turnStartEntryId}`
- 使召回有入口（现状 L5 行无任何 ID，用户无从召回）

**理由**：R3 让 L5 可召回，但用户需要知道"拿什么 ID 去召回"。

### R5 · 边界：不做 L6+，不管 L4→L5 之外的选择粒度

- L5 之上不再加层（L6/L7…）
- 不改 L1→L4 的选择粒度与阈值
- L5 不限制大小

**理由**：探针显示 L5 层体积远达不到需要新层的规模（L5 单行 16–32 tok，装不满任何合理预算）。加层是解一个不存在的问题。

## 3. 明确不做（删除项）

| 项 | 理由 |
|---|---|
| `startsNewTask` 字段 | 探针：同提示词复跑 3 次，边界 Jaccard **0.41–0.58**，结果不可复现 |
| `taskAnchorId` 字段 | 按任务聚合被否证后无意义；改用现算的 `turnStartEntryId`（零映射层） |
| 按任务聚合 / 按任务累加 reserve | 同 `startsNewTask` |
| `mergeGroups` 计划期产物 | R1 取消组概念 |
| 固定步长 2 分组（原 T158 裁定） | R1 下逐条即天然粒度 1，步长概念消失 |
| L3 视图召回（旧 spec 裁定 6） | 由 R3 取代；合并取消后无存在理由 |
| L5 拒绝召回 + `rejected` 计数（M9） | 由 R3 取代；不再有"拒发"这种状态 |
| L5 渲染聚合分支（`ledger.ts:170-192`） | 一 turn 一描述后永远只切 1 条，且该分支不渲染 ↩ID（挡住 R4） |
| `（N 条已合并）` 后缀 | R1 下 N 恒为 1，后缀无意义 |
| Codex P3 计数重写逻辑（`ledger.ts:181-187`） | 随聚合分支一并消失；它修的问题（两批次碰巧同描述被误聚合）不再存在 |

**净效果：这是一次以删除为主的改动。**

## 4. 验收标准

实现完成后，以下应全部成立：

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | 每条 L5 条目对应恰好一个 turn | `merged.description` 各不相同；无组共享 |
| 2 | 900 条 L4 的降级调用次数 ≈ 45（非 900、非 15） | 计数断言 |
| 3 | 某条生成失败时不波及其他条 | 单条重跑 + 保持 L4 的测试 |
| 4 | recall 任意 L5 行的 ↩ID → 返回整段原文（含工具过程） | 与 L3/L4 行为对比测试 |
| 5 | 不再出现「不可恢复」文案 | 删除旧测试 + 新断言 |
| 6 | L5 行含 ↩ID | 渲染快照 |
| 7 | 不含 L5 的会话，装配渲染**逐字节不变** | 回归防护测试 |
| 8 | `rejected` 字段从统计中消失，calls/hits 计数正确 | 单元测试 |

## 5. 已知代价与风险

| 项 | 说明 | 处置 |
|---|---|---|
| **成本** | 约 45 次调用 / 约 20 分钟后台（现状约 15 次） | 接受；换来标识保留与正确性 |
| **L5 层体积变大** | 压缩率 0.492 且每条独立，比"组共享一行"占更多 token | 接受；L5 是极低频路径 |
| **耗时波动** | 实测同规模批次 39s vs 99s（2.5 倍） | 无法控制，reasoning 模型固有 |
| **输入格式偏离** | spec 选干净字段，现状代码喂带 `T0` 前缀与 ↩ID 的文本 | ✅ 已验证（2026-09-27，2 批 20 条零串位） |
| **存量旧数据** | 旧 L5（一组共享描述 + 旧后缀）与新数据混排 | 不迁移，原样保留；渲染各占一行 |
| **`merged` 字段语义漂移** | 从「组描述」变「单 turn 描述」，字段名未改 | README 说明 |
